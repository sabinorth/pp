# Путеводитель «Прага + Париж, октябрь 2026»

Личный интерактивный сайт для двух путешественниц: Сабины и её подруги. Обе программистки, быстро устают физически, поэтому щадящий темп важнее, чем охват. Сайт помогает готовиться (игры, рекомендации) и ориентироваться на месте (карта, план дня). Основное использование — с телефона на улице.

## Поездка

| Даты | Город | Отель |
|---|---|---|
| 1–5 октября 2026 (чт–пн) | Прага | Aparthotel Austria Suites |
| 5–10 октября 2026 (пн–сб) | Париж | Hôtel De La Porte Dorée |

- 5 октября (пн) — переезд Прага → Париж. В этот день нельзя планировать ничего тяжёлого.
- 8 октября (чт) — Версаль, целый день.
- Рейсы (местное время):

  | Дата | Рейс |
  |---|---|
  | 1.10 (чт) | прилёт в Прагу (аэропорт Вацлава Гавела, PRG) в 19:30 |
  | 5.10 (пн) | вылет из Праги в 12:20 → прилёт в Париж CDG в 14:15 (Шенген) |
  | 10.10 (сб) | вылет из Парижа CDG в Алматы в 12:55 (международный рейс, в CDG за 3 часа) |

  Трансферы — `practical.json` → `transfers` и пункты в `days.json`.
- Точные адреса и координаты отелей нужно найти через поиск и показать пользователю на подтверждение.

## Стек (не менять без согласования)

- Статический сайт без сборки: `index.html` + ES-модули в `js/` + `css/`. Без фреймворков и npm-зависимостей в рантайме.
- Карта: Leaflet (CDN, закреплённая версия) + тайлы OpenStreetMap. Без Google Maps API и без ключей.
- Данные: JSON в `data/`. Весь контент живёт в данных, в коде контента нет.
- Роутинг: hash-роутинг (`#/map?city=paris&place=louvre`, `#/day/2026-10-08`, `#/game/versailles`), чтобы разделы могли ссылаться друг на друга.
- PWA: `manifest.json` + service worker, офлайн-кэш страниц и данных. Кэш тайлов карты не нужен.
- Деплой: GitHub Pages.
- Локальный запуск: `python3 -m http.server 8000`, потому что fetch JSON не работает с file://.

  "coords": [48.8606, 2.3376],
  "address": "...",
  "summary": "1–2 предложения, зачем идти",
  "description": "3–5 предложений",

  "price": { "avg_check_eur": 15, "ticket_eur": 22, "note": "" },
  "booking": { "required": true, "url": "..." },
  "photos": [{ "url": "...", "credit": "автор", "license": "CC BY-SA 4.0", "source": "URL на Wikimedia Commons" }],
  "effort": {
    "level": "low | mid | high",
    "walk_km": 2.5,
    "stairs": "none | some | many",
    "queue": "none | short | long",
    "seating": true,
    "toilet": true,
    "duration_min": 150
  },
  "transit_hint": { "from_hotel_min": 25, "transfers": 1, "note": "в метро на пересадке много лестниц" },

### Впечатления, события, идеи (подробно — `feature-experiences.md`)

- `experience` — занятие, мастер-класс, необычный формат, маршрут. На карте в слое «✨ Впечатления».
- `event` — привязано к датам: `"dates": [{ "date": "2026-10-03", "time": "20:00", "note": "…" }]`. Тот же слой.
- `idea` — впечатление без адреса: `"coords": null`, на карте нет маркера. Видна в списке «💭 Идеи» на карте и в «Советах».
  `"candidates": ["id", …]` — конкретные точки, где это можно сделать; у точки-кандидата `"idea_id": "…"`. Подсветка кандидатов на карте: `#/map?city=paris&candidates=<id идеи>`.
- Дополнительные поля (все необязательные):
  - `description_long` — авторский текст из подборки целиком, абзацы через `\n\n`. Не сокращать.
  - `tips[]`, `how_to[]` (пошагово), `fact_notes[]` (расхождения текста с источниками).
  - `origin` — откуда точка: `user-list-paris-1`, `user-list-paris-2`, `user-list-prague`.
  - `pairs_with[]` — id точек того же города, которые удобно совместить.
  - `route_stops: [{ "name": "…", "coords": [lat, lng], "note": "…", "place_id": "…" }]` — для маршрутов; `coords` точки = старт. На карте пунктир, пока точка открыта. `place_id` — остановка-точка (ссылка в шторке, её закрытия видны в «Проверке дня»).
  - Щадящие маршруты — `experience` с тегом `"щадящий маршрут"` и `route_stops`: карточки в «Советах», в план дня встают одним пунктом.
  - `best_time: [{ "time": "после 22:00", "note": "ночь" }]` — лучшее время без конкретной даты.
- Метка «☔ на дождь» — тег `"на дождь"` в `tags`.

Ссылки на маршруты НЕ хранятся, они генерируются из координат:
`https://www.google.com/maps/dir/?api=1&origin=LAT,LNG&destination=LAT,LNG&travelmode=transit`
(и в обратную сторону: из точки в отель).

### Часы работы для проверок

- `hours.slots` — часы по дням недели (0 = вс), только если они однозначно следуют из `hours.text`. Интервал с концом раньше начала идёт за полночь, `"24:00"` — до полуночи. Нет `slots` — ⏰ в «Проверке дня» не проверяется.
- `hours.closed_dates` — закрытые даты сверх `closed_weekdays` (праздники).
- `hotels.json → dates.arrive_time / leave_time` — когда мы в отеле в день заезда и когда выезжаем в день выезда (из трансферов). По ним ✈️ в «Проверке дня» и «после отъезда» у дат событий.

## Ручной план дня (`js/plan.js`)

- Claude НЕ распределяет впечатления, события и идеи по дням в `days.json`. План собирает пользователь сам.
- Страница дня = базовые пункты из `days.json` (план А или Б) + добавленные вручную кнопкой «+ В план». Добавленные пункты общие для А и Б.
- Любой пункт: ↑↓ (ручной порядок отдельно для А и Б), время и заметка. Базовый пункт можно «убрать» (скрыть) и вернуть, добавленный — удалить.
- «+ В план» предлагает только дни, когда мы в городе точки (5.10 — оба города). Если события нет в этот день (`dates`) или место закрыто (`hours.closed_weekdays`, 0 = вс), показывается мягкое предупреждение, но добавить можно.
- Энергобюджет считает видимые пункты с учётом добавленных. В дни перелёта (заезд или выезд из отеля: 1, 5, 10.10) порог ниже на 2.
- «Проверка дня» (checks.js) пересчитывается при каждой отрисовке: ⚠️ закрыто/нет события, ⏰ время вне `hours.slots`, ✈️ до заселения/после выезда, 🎟 бронь, 🚇 забастовка (`warnings` с `kind: "strike"` показываются только здесь), 😴 перегрузка, иначе ✅.
- «Отправить день текстом» — план дня со ссылками на точки через `navigator.share`, фолбэк — буфер обмена.
- Хранение: localStorage (`trip2026:v1` → `dayplans`, `plans`) через store.js. Старое «Моё» (`mine`) мигрирует автоматически.
- Перенос между телефонами: «Экспорт плана» (JSON-файл), «Импорт плана», «Поделиться ссылкой» (`#/plan?import=<base64url>`, перед заменой — подтверждение).

## Тема оформления

- `<html data-theme="emo|plain">`, по умолчанию `emo` (эмо-MySpace, всегда тёмная). Ставится инлайн-скриптом в `index.html`, переключатель — в «Советы → Практическое → Настройки» (`store` → `theme`).
- Эмо — только рамка: фон, шапки блоков `.mod-head`, h1, декор. Текст, кнопки, карта — контраст WCAG AA, тайлы не трогать. Цвета — токены в `:root[data-theme="emo"]`.
- Шапка «<Имя>'s …» — `whose(title, who)` из ui.js; имена — из игроков (`players.js`). `.emo-only` / `.not-emo` — разметка только для одной из тем.
- Анимации только CSS, все выключаются при `prefers-reduced-motion`. Никаких GIF, внешних картинок и персонажей — только эмодзи и CSS/SVG-декор.
- MySpace-механики: Mood (energy.js), Top 8 (`top8`), «Currently listening» (`songs` по дате), заметки как стена комментариев, счётчик на «Плане». В экспорт плана `top8` и `songs` не входят.

## Жёсткие правила

1. **Не выдумывать факты.** Часы работы, цены, закрытые дни, исторические факты — только из найденных источников, с полем `source`. Если что-то не удалось проверить, ставь `"verified": false` и не заполняй поле догадкой.
2. **Фото — только с Wikimedia Commons**, с автором и лицензией. Если подходящего фото нет, оставь пустой массив и не бери картинки из других источников.
3. **Язык интерфейса и контента — русский.** Названия дублировать в оригинале (`name_local`).
4. **Mobile-first.** Крупные зоны нажатия (от 44px), читаемо на ярком солнце, тёмная тема по системной настройке.
5. **Нагрузка — первичная информация.** Везде, где есть активность, видно `effort` понятными значками.
6. **Малыми шагами.** После каждого логического куска — рабочее состояние и git-коммит с понятным сообщением.
7. **Не расширять объём без спроса.** Видишь хорошую идею — предложи её в конце ответа, но не реализуй.
8. **Экономия лимитов.** Не перечитывать без нужды большие JSON целиком, не переписывать файлы полностью ради мелких правок.
